# 视觉结构先验路由实验路线对比：保守验证 vs 推荐主线

## 0. 背景与目标

当前课题的核心问题不是“ViT 能否直接做时序预测”，也不是“ViT 能否在单一窗口设置下拟合专家标签”，而是：

> 视觉模块能否从通道独立的 sample-channel 历史窗口中学习跨窗口长度、预测 horizon 和数据源都尽量稳定的时序结构先验，并用该先验驱动多个异构时序专家的连续自适应融合？

因此，ViT/视觉 encoder 在本课题中的角色应优先定义为“时序结构先验提取器”，continuous router/gate 是下游验证器。官方 TSF cell、通道级 STL 和窗口级 proxy 都服务于解释、分层和辅助监督，不应混成同一个标签层次。

围绕这个问题，可以先考虑两条主要路线：

1. **路线 1：保守验证路线**
   先不引入复杂的 TSF 分层和多任务微调，直接验证“视觉时序结构 embedding 能否迁移到异构专家连续融合，并降低 oracle gap”。

2. **路线 2：推荐主线**
   以 QuitoBench 的 TSF 结构分层为主实验场景，先做专家画像，再训练/校准视觉结构 encoder 和 continuous gate，最后验证 few-shot、跨 window/horizon 和跨 cell 泛化。

两条路线不是互斥关系，而且都值得做。它们回答的是两个层次的问题：

- **路线 1** 回答“视觉伪图像 router 在通用预测场景中是否有稳定收益”，它是方法有效性和工程可行性的基础实验。
- **路线 2** 回答“视觉结构先验在 TSF 分层和 few-shot 条件下是否具有可解释、可泛化的专家路由能力”，它是更强的研究主线。

因此更合理的定位不是“路线 1 做完就切到路线 2”，而是：

> 路线 1 和路线 2 都做。路线 1 建立通用有效性与工程闭环，路线 2 建立结构化解释、few-shot 场景和论文主贡献。

截至 Stage 0.7，QuitoBench 官方 TSF codebook 已由 Stage 0.6b 确认，通道级 full-length STL 验证显示 forecastability 维度 100% 匹配，cluster 24 的官方 `lowT_lowS_highF` 解释得到通道均值口径支持；但 trend/seasonality 在 cluster 6、8、26 上仍有本地口径差异。因此路线 2 应使用官方 codebook 做分层报告，同时避免把 official cluster 或 STL cell 当作 sample-channel router 的硬标签。

## 1. 路线 1：保守验证路线

### 1.1 核心命题

路线 1 的核心命题是：

> 即使不显式引入 QuitoBench TSF cell，也可以通过专家 oracle error 监督训练 continuous gate，验证视觉时序结构 embedding 是否能提供有效的样本级异构专家融合信号。

这条路线的重点是快速回答两个基础问题：

> 视觉 encoder 从伪图像/视觉张量中抽出的表示，是否比统计 meta-feature 或普通时序 encoder 更适合预测专家偏好？

> 该表示是否能在不同 `history_len`、`pred_len` 或数据源之间保持可迁移性，而不是只记住单一窗口设置下的 oracle 分布？

### 1.2 模型框架

输入窗口第一版采用通道独立口径：

```text
X_channel in R^{B x L}
```

如果上游数据是多变量：

```text
X in R^{B x L x C}
```

则默认展开为 `B*C` 个 sample-channel window 进入视觉 encoder；通道融合只作为后续消融。

GPU 伪图像化或视觉张量化：

```text
I = Phi_gpu(X_channel)
```

其中 `Phi_gpu` 第一版只保留低成本、尽量保留时间维度的伪图像：

- period reshape 2D
- GAF/GADF
- FFT/STFT power map

视觉编码：

```text
z_v = ViT(I)
```

连续 gate：

```text
w = softmax(MLP([z_v, s_proxy, c_config, m_scale]) / tau)
```

其中 `s_proxy` 是可选 sample-channel light proxy，`c_config` 是 `history_len/pred_len/period/subset` 等配置 embedding，`m_scale` 是归一化统计量和尺度元数据。visual-only 消融可只使用 `z_v`。

专家预测：

```text
y_k = Expert_k(X)
```

融合输出：

```text
y_hat = sum_k w_k * y_k
```

在线推理建议采用 `top-k soft routing`：gate 先选出少量候选专家，再在 top-k 内做连续加权。路线 1 中，视觉 encoder 可以先冻结，只训练 projection/gate。这样可以把变量压到最低。

### 1.3 专家池

路线 1 不需要一开始做大规模专家 profiling，建议固定 3-4 个代表性专家：

- seasonal naive：低成本统计基线
- DLinear：分解线性模型，覆盖 trend/seasonal 简单结构
- PatchTST：patch transformer 专家
- TSMixer 或 TimeMixer：MLP/multiscale 专家

如果算力有限，第一版可以只用：

- DLinear
- PatchTST
- TSMixer

但建议保留 seasonal naive，因为它能防止复杂模型在强季节样本上被简单方法击败而实验没有捕捉到。

### 1.4 训练监督

路线 1 的主要监督来自专家 oracle error。

先离线训练或加载专家，对每个训练窗口计算：

```text
e_k = Loss(y_k, y_true)
```

然后把误差转成 soft routing target：

```text
q_k = softmax(-e_k / T_oracle)
```

router 训练目标：

```text
L_route = KL(q || w)
```

也可以加入最终预测损失：

```text
L_pred = Loss(sum_k w_k * y_k, y_true)
```

第一版推荐：

```text
L = L_route + alpha * L_pred
```

其中 `L_route` 是主监督，`L_pred` 用较小权重，避免 router 过早塌缩到平均最强专家。

### 1.5 实验流程

#### Step 1：选择数据集

路线 1 可以使用传统 LTSF 数据集快速启动：

- ETTm1 / ETTm2
- Electricity
- Weather
- Traffic

也可以直接用 QuitoBench 抽样，但不强制做 8-cell 分层。

推荐优先：

```text
ETTm1 + Weather + QuitoBench small subset
```

这样既有常见 baseline，又能初步验证 Quito 分布。

#### Step 2：训练专家

统一输入长度和预测长度，例如：

```text
L = 96, H = 96
L = 336, H = 96
```

每个专家独立训练，记录：

- validation MSE/MAE
- inference latency
- 每个样本的预测误差

#### Step 3：构建 oracle target

对每个样本形成：

```text
[e_1, e_2, ..., e_K]
```

再生成：

- best expert id
- soft oracle weight
- oracle ensemble upper bound

#### Step 4：训练视觉 router

比较不同 router 输入：

- statistical features
- raw time-series encoder embedding
- frozen ViT embedding
- fine-tuned ViT embedding
- visual + statistical features

路线 1 中，ViT 微调可以只做最后几层或 LoRA，不做复杂多任务。

#### Step 5：评估融合效果

主要比较：

- best fixed expert
- uniform ensemble
- global weighted ensemble
- statistical router
- time-series encoder router
- visual router
- visual + statistical router

### 1.6 指标

预测指标：

- MSE
- MAE
- MASE
- SMAPE

路由指标：

- oracle gap
- top-1 expert accuracy
- soft target KL
- routing entropy
- expert utilization entropy

工程指标：

- GPU imageization latency
- router latency
- total inference latency

### 1.7 优点

路线 1 的优点：

- 变量少，工程启动快。
- 能快速判断视觉伪图像是否有基本价值。
- 不依赖 TSF cell 构造质量。
- 很适合作为后续主线的 preliminary experiment。
- 如果效果不好，可以快速调整伪图像和专家池，损失较小。

### 1.8 风险

路线 1 的主要风险：

- 如果只报整体 MSE/MAE，容易掩盖不同结构 regime 的行为差异。
- 没有显式结构标签，难以证明 ViT 学到的是时序结构语义，而不是伪图像编码伪迹。
- 与 TimeFuse 的差异可能不够强，容易被质疑只是把 meta-feature router 换成 visual router。
- 如果专家池互补性不足，router 的价值会被低估。

### 1.9 路线 1 的适用定位

路线 1 最适合回答：

> 这个方向有没有快速实验信号？

它不适合直接作为最终论文主线，但适合作为：

- 先导实验
- 工程验证
- 伪图像模块筛选
- router 训练流程调试

## 2. 路线 2：推荐主线

### 2.1 核心命题

路线 2 的核心命题是：

> 在 QuitoBench 的 TSF 结构分层下，不同专家在 trend、seasonality、forecastability 组合 cell 中存在可测的偏好和互补性；经过 TSF 结构语义微调的视觉编码器能够从 GPU 端内生伪图像张量中提取结构先验，并在 few-shot 条件下生成更有效的连续专家融合权重。

这条路线把课题从“视觉模型能不能用于时序”收敛为：

> 视觉结构先验能否帮助 few-shot 专家路由？

### 2.2 总体模型框架

输入：

```text
X in R^{B x L x C}
```

GPU 伪图像：

```text
I = Phi_gpu(X) in R^{B x V x H x W}
```

视觉结构编码：

```text
z_v = ViT_theta(I)
```

可选统计特征：

```text
s = MetaFeature(X)
```

路由：

```text
w = Router([z_v, s]) 
```

主方法：

```text
w = softmax(g([z_v, s]) / tau)
```

稀疏版本：

```text
w = entmax(g([z_v, s]) / tau)
```

专家预测：

```text
y_k = Expert_k(X)
```

融合：

```text
y_hat = sum_k w_k * y_k
```

### 2.3 QuitoBench TSF 分层

路线 2 以 QuitoBench 为主数据集，而不是传统 LTSF 数据集。

核心结构标签：

- trend strength
- seasonality strength
- forecastability

将三类属性离散化后形成：

```text
2 trend levels x 2 seasonality levels x 2 forecastability levels = 8 TSF cells
```

每个 cell 单独报告结果。总体结果必须同时给：

- macro-average over cells
- weighted-average over samples

这样可以避免大 cell 掩盖小 cell，也避免整体平均掩盖结构差异。

### 2.4 Stage A：Expert Profiling

#### 目标

先证明专家之间确实存在结构互补性。

如果不同 TSF cell 中所有专家排序都差不多，那么 router 的研究价值会下降。因此专家画像是路线 2 的第一步。

#### 候选专家

初始候选池建议：

- seasonal naive
- DLinear
- FITS
- PatchTST
- iTransformer
- TSMixer / TimeMixer
- Crossformer

候选池不直接等于最终专家池。最终只保留 3-4 个互补性强、推理成本可控的专家。

#### 实验流程

1. 在 QuitoBench hour/min config 上抽样构建训练、验证、测试窗口。
2. 为每个窗口计算或加载 TSF 标签。
3. 按 8 个 TSF cell 分层。
4. 统一训练候选专家。
5. 计算每个 cell 中每个专家的性能。
6. 输出 `cell x model` 矩阵。
7. 计算：
   - average rank
   - cell-wise win rate
   - oracle ensemble contribution
   - inference latency
   - parameter count
   - few-shot adaptation cost
8. 筛选最终专家池。

#### 关键输出

- 哪些专家在强趋势 cell 更好。
- 哪些专家在强季节 cell 更好。
- 哪些专家在低 forecastability cell 更稳。
- 哪些专家虽然平均分一般，但在特定 cell 有不可替代贡献。
- oracle ensemble 上界是否明显高于 best fixed expert。

如果 oracle ensemble 上界不高，说明专家互补性不足，需要重选专家池。

### 2.5 Stage B：GPU 内生伪图像与输入消融

#### 目标

验证哪些伪图像最适合让视觉编码器识别 TSF 结构。

#### 第一批伪图像

MVP 推荐：

- period reshape 2D
- GAF/GADF
- FFT/STFT power map

暂缓：

- RP
- MTF
- CWT

原因是 RP/MTF/CWT 的超参数和计算成本更复杂，容易把第一阶段拖成图像化工程。

#### 输入组合

三种组合方式：

1. 单视图输入。
2. 多视图 channel stack。
3. 多视图 token/view attention。

MVP 推荐先做：

```text
单视图 + channel stack
```

view attention 放到第二阶段。

#### ViT 输入尺寸消融

需要比较：

1. resize 到 224 x 224 + pretrained ViT
2. 小尺寸 H x W patchify + positional embedding interpolation
3. custom patch embedding + ViT encoder

推荐主方法暂定为第 2 种，但必须用实验确认。

### 2.6 Stage C：视觉结构语义微调

#### 目标

让 ViT 学到 TSF 结构语义，而不是只学习伪图像纹理。

#### 第一版损失

路线 2 的 MVP 不建议一次加入所有损失。

第一版只保留：

```text
L = L_tsf + lambda_route * L_route
```

其中：

```text
L_tsf = L_trend + L_seasonality + L_forecastability + L_cell
```

`L_route` 来自专家 oracle error soft label：

```text
q_k = softmax(-e_k / T_oracle)
L_route = KL(q || w)
```

#### 后置损失

以下内容放到增强实验：

- `L_align`：对齐强时序模型中间表征
- `L_rec`：mask 后重建原始序列或伪图像 patch

后置原因：

- 两者都会显著增加变量。
- 如果主实验有效，先证明 `L_tsf + L_route` 已经足够。
- 如果一开始全开，实验成功后难以解释是哪一部分起作用。

### 2.7 Stage D：Few-shot Continuous Routing

#### few-shot 定义

MVP 推荐：

> QuitoBench cell-level low-shot router adaptation。

即每个 TSF cell 内只给少量样本校准 router，而不是一开始做完全 held-out cell。

shot 设置：

- 1-shot
- 5-shot
- 10-shot
- 50-shot

#### 可适配模块

从轻到重：

1. 只调 router temperature。
2. 只训练 router last layer。
3. 训练完整 router。
4. LoRA / adapter 微调 ViT。
5. 专家也做 few-shot 微调。

MVP 建议先比较 1-3。第 4 和第 5 作为扩展。

#### 泛化压力测试

在主实验完成后，再做：

```text
leave-one-cell-out
```

流程：

1. 在 7 个 TSF cell 上训练视觉 router。
2. 完全不使用剩下 1 个 cell 的训练样本。
3. 在留出的 cell 上测试。
4. 轮换 8 次。

这个实验难度较高，不建议作为 MVP 第一实验，但适合作为论文中验证“跨结构泛化”的关键实验。

### 2.8 对照组

路线 2 必须包含：

- best fixed expert
- uniform ensemble
- global weighted ensemble
- statistical meta-feature router
- time-series encoder router
- TSF 8-class hard router
- VisMoE-style hard router
- visual continuous router
- visual + statistical continuous router

其中：

- `TSF 8-class hard router` 用来判断显式结构标签能做到什么程度。
- `VisMoE-style hard router` 用来和视觉离散路由对齐。
- `statistical meta-feature router` 是最关键 baseline，因为它直接挑战“是否需要 ViT”。

### 2.9 指标

预测指标：

- MSE
- MAE
- MASE
- SMAPE

路由指标：

- oracle gap
- routing entropy
- expert utilization entropy
- routing-regime agreement
- top-k oracle coverage

结构语义指标：

- trend classification/regression score
- seasonality classification/regression score
- forecastability classification/regression score
- 8-cell classification accuracy / macro-F1

工程指标：

- GPU imageization latency
- ViT/router latency
- total inference latency
- active expert count

### 2.10 预期结论形式

路线 2 最终希望支撑以下结论：

1. QuitoBench 的不同 TSF cell 中存在稳定的专家偏好。
2. 内生伪图像中的视觉表示能够预测 TSF 结构标签。
3. 视觉连续路由能比 hard router 更接近 oracle ensemble。
4. 在 few-shot 条件下，调 router 比调专家更高效。
5. visual + statistical router 可能是最强实用版本，但 visual-only router 应该证明视觉结构先验本身有效。

## 3. 两条路线对比

| 维度 | 路线 1：保守验证 | 路线 2：推荐主线 |
| --- | --- | --- |
| 主要目标 | 快速验证视觉 router 是否有信号 | 系统证明视觉结构先验适合 few-shot 路由 |
| 主数据 | 传统 LTSF + Quito small subset | QuitoBench TSF 分层 |
| 专家池 | 固定 3-4 个专家 | 先 profiling，再筛选 3-4 个专家 |
| ViT 训练 | 冻结或轻微微调 | TSF 结构语义微调 + route soft label |
| few-shot | 可选，弱化处理 | 主实验重点 |
| 解释性 | 较弱 | 强 |
| 和 TimeFuse 区分 | 一般 | 明确 |
| 工程复杂度 | 低 | 中高 |
| 论文主线潜力 | 中 | 高 |
| 失败成本 | 低 | 中 |

## 4. 我的评价

### 4.1 路线 1 的价值

路线 1 值得完整做，而不只是作为路线 2 的前置 smoke test。

它的第一层价值是快速排雷：

- GPU 伪图像化流程是否稳定。
- ViT embedding 是否包含有用路由信号。
- oracle soft label 是否能训练 router。
- 专家融合是否真的有上界空间。
- visual router 是否至少不弱于普通时序 encoder router。

它的第二层价值是提供“通用场景下的视觉路由证据”：

- 在传统 LTSF 数据集上证明方法不是只适配 QuitoBench。
- 在不依赖 TSF 标签的情况下证明 visual router 能学习专家偏好。
- 作为 TimeFuse-style statistical router 的直接对照。
- 为路线 2 中的 QuitoBench 结构化结论提供外部支撑。

因此路线 1 可以作为论文中的一个完整实验模块，而不是只作为内部工程验证。它的短板是解释性不如路线 2，因为它没有强结构分层；但这不等于它不重要。它回答的是“是否普遍有效”，路线 2 回答的是“为什么有效、在哪些结构上有效、few-shot 下是否更有效”。

### 4.2 路线 2 的价值

路线 2 更适合作为正式研究路线。

它的优势在于：

- QuitoBench 的 TSF 分层天然适合回答结构先验问题。
- cell-level reporting 能避免整体平均掩盖模型行为。
- expert profiling 能证明 router 的必要性。
- `L_tsf + L_route` 能把视觉语义和专家偏好连接起来。
- few-shot router adaptation 能形成明确应用场景。
- continuous routing 能和 VisMoE-style hard routing 区分。

路线 2 的风险是工程量更大，因此需要先把 MVP 控制住：

- 不上 RAG。
- 不上 Prototype Bank。
- 不一开始做 `L_align/L_rec`。
- 不穷举所有伪图像。
- 不一开始做 leave-one-cell-out。

## 5. 推荐执行顺序

我建议采用双路线设计：

> 路线 1 和路线 2 都作为正式实验模块，但承担不同职责；工程上先跑路线 1 的最小闭环，再扩展到路线 2 的结构化实验。

具体顺序：

1. 先用路线 1 打通最小闭环：
   - 固定 3-4 个专家。
   - 固定 2-3 个伪图像。
   - 冻结 ViT 或轻微微调。
   - 用 oracle error 训练 router。
   - 看 visual router 是否降低 oracle gap。

2. 保留路线 1 作为完整实验模块继续完善：
   - 扩展到多个传统 LTSF 数据集。
   - 系统比较 visual router、statistical router、time-series encoder router。
   - 报告整体性能、oracle gap、延迟和专家利用率。
   - 用它证明方法在非 QuitoBench 场景下也成立。

3. 同步进入路线 2 的结构化主实验：
   - QuitoBench TSF cell 构造。
   - 大候选专家 profiling。
   - 筛选最终专家池。
   - ViT 学 `L_tsf + L_route`。
   - 做 few-shot continuous routing。

4. 如果路线 1 的信号很弱，不是放弃路线 2，而是先定位问题：
   - 专家池是否没有互补性？
   - 伪图像是否没有表达结构？
   - ViT/router 是否训练方式不合适？
   - 数据集整体平均是否掩盖了结构差异？

   如果问题来自传统数据集结构混杂，路线 2 的 QuitoBench 分层反而更有必要，因为它能把隐藏的结构差异显式拆出来。

---

## 6. 最终推荐

最终推荐路线是：

> 双路线都做：路线 1 证明视觉路由的通用有效性和工程可行性，路线 2 证明视觉结构先验在 TSF 分层与 few-shot 场景下的可解释优势。

换句话说：

- **路线 1 是通用有效性实验，不只是前置验证。**
- **路线 2 是结构化主实验，承担核心论文贡献。**
- **工程启动先做路线 1 的最小闭环。**
- **实验资产必须为路线 2 复用：专家预测、oracle error、伪图像模块、router 框架都尽量共享。**
- **第一篇论文不要加入 RAG/Prototype Bank。**
- **MVP few-shot 定义采用 QuitoBench cell-level low-shot router adaptation。**
- **leave-one-cell-out 放在主实验成功后的泛化压力测试。**

这能同时控制风险和保持创新点：

1. 路线 1 证明方法在常规数据集和非结构化评估下仍有价值。
2. 路线 2 解释这种价值来自哪些 TSF 结构、哪些伪图像和哪些路由机制。
3. 两条路线互相补强：路线 1 防止方案只适配 QuitoBench，路线 2 防止路线 1 只有结果而缺乏机制解释。
